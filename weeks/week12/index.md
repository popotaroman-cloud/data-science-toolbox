## 1. จากกราฟทีละตัวแปรสู่ข้อมูลหลายมิติ

สัปดาห์ที่ 9–11 เราดูข้อมูลทีละ 1–2 ตัวแปร เช่น time series ของสถานีเดียว หรือเปรียบเทียบ 2 ภาค แต่ประเทศไทยมีสถานีหลายสิบแห่ง ถ้าอยากรู้ว่า *"สถานีไหนมีรูปแบบตามฤดูกาลคล้ายกัน"* เราต้องดูทุกสถานีพร้อมกันทั้ง 12 เดือน ซึ่งเป็นข้อมูล 12 มิติ

| คำถามใน `questions.md` (ตัวอย่าง) | เทคนิคสัปดาห์นี้ |
|---|---|
| สถานีในภาคเหนือมีรูปแบบฤดูกาลต่างจากกรุงเทพฯ หรือไม่ | PCA + clustering ของ monthly profile |
| วันที่ค่าสูงผิดปกติเป็นไฟป่าจริง หรือเซนเซอร์เสีย | การวิเคราะห์ outlier ตามบริบท |
| ถ้าจะเชื่อม PM2.5 กับข้อมูลผู้ป่วย ต้องระวังอะไร | PDPA + ข้อมูลสังเคราะห์ |

### เตรียมเมทริกซ์ monthly profile

หนึ่งแถวคือหนึ่งสถานี หนึ่งคอลัมน์คือค่าเฉลี่ย PM2.5 ของเดือนนั้น (เฉลี่ยทุกปีที่มีข้อมูล)

```python
import duckdb

con = duckdb.connect("data/pm25.duckdb", read_only=True)
monthly = con.sql("""
    SELECT station_id, month(date) AS m, avg(pm25_mean) AS pm25
    FROM daily_pm25_clean
    WHERE is_complete
    GROUP BY station_id, m
""").df()

profile = monthly.pivot(index="station_id", columns="m", values="pm25")
print(profile.shape)                 # เช่น (80, 12)
print(profile.isna().sum().sum())    # มีเดือนที่ไม่มีข้อมูลกี่ช่อง
```

scikit-learn ส่วนใหญ่รับค่าว่างไม่ได้ ต้องตัดสินใจอย่างมีเหตุผล (ทบทวนสัปดาห์ที่ 7) เช่น ตัดสถานีที่ขาดเกิน 2 เดือน แล้วเติมที่เหลือด้วยค่าเฉลี่ยของเดือนเดียวกันในภาคเดียวกัน และ**บันทึกจำนวนสถานีที่ถูกตัด**ไว้ในข้อจำกัด

```python
keep = profile.isna().sum(axis=1) <= 2
profile_filled = profile[keep].apply(lambda col: col.fillna(col.mean()))  # แบบง่าย: เติมด้วยค่าเฉลี่ยของเดือนนั้น
print(f"ตัดออก {(~keep).sum()} สถานี")
```

## 2. ทำไมต้อง scale ข้อมูล

PCA และ KMeans ใช้ **ระยะทาง** และ **ความแปรปรวน** ถ้าคอลัมน์หนึ่งมีค่าแปรปรวนสูงกว่ามาก คอลัมน์นั้นจะครอบงำผลลัพธ์ เช่น PM2.5 เดือนมีนาคมในภาคเหนืออาจแกว่ง 20–120 µg/m³ ขณะที่เดือนกรกฎาคมแกว่งแค่ 5–20 µg/m³ ถ้าไม่ scale ผลลัพธ์จะเกือบเท่ากับ "ดูแค่เดือนมีนาคม"

ปัญหาจะชัดขึ้นอีกเมื่อรวมตัวแปรต่างหน่วย เช่น PM2.5 (µg/m³) กับ CO (ppm) หรือละติจูด (องศา)

```python
from sklearn.preprocessing import StandardScaler

X = StandardScaler().fit_transform(profile_filled)   # แต่ละเดือน: mean 0, sd 1
```

มี 2 คำถามที่ต้องเลือกให้ตรงกับคำถามวิจัย

| วิธี | ทำอะไร | กลุ่มที่ได้สะท้อน |
|---|---|---|
| scale ตามคอลัมน์ (StandardScaler) | ทุกเดือนมีน้ำหนักเท่ากัน | ทั้ง *ระดับ* และ *รูปร่าง* ของฤดูกาล |
| หารแต่ละแถวด้วยค่าเฉลี่ยของสถานีนั้นก่อน | ตัดผลของระดับรวมออก | *รูปร่าง* ของฤดูกาลอย่างเดียว (สูงช่วงไหน) |

ไม่มีวิธีใดถูกเสมอ ให้เขียนเหตุผลที่เลือกไว้ใน notebook

## 3. PCA: ลดมิติเพื่อมองเห็นโครงสร้าง

**Principal Component Analysis (PCA)** หาทิศทางใหม่ (principal component, PC) ที่ข้อมูลแปรปรวนมากที่สุด PC1 อธิบายความแปรปรวนได้มากที่สุด PC2 รองลงมาและตั้งฉากกับ PC1

```python
import numpy as np
import pandas as pd
from sklearn.decomposition import PCA

pca = PCA(n_components=3, random_state=42)
scores = pca.fit_transform(X)
print(pca.explained_variance_ratio_.round(2))   # เช่น [0.71 0.15 0.05]

loadings = pd.DataFrame(pca.components_.T, index=profile.columns,
                        columns=["PC1", "PC2", "PC3"])
loadings.round(2)
```

### การตีความ

- **explained variance ratio:** ถ้า PC1 + PC2 รวมกันเกิน ~80% กราฟ 2 มิติของ PC1–PC2 แทนข้อมูลเดิมได้ค่อนข้างดี
- **loadings:** น้ำหนักของแต่ละเดือนใน PC นั้น ดูทั้งเครื่องหมายและขนาด

| รูปแบบ loadings (ตัวอย่าง) | ความหมายที่เป็นไปได้ |
|---|---|
| PC1 มีค่าบวกใกล้เคียงกันทุกเดือน | "ระดับรวม" สถานีที่ score สูงคือสถานีที่สกปรกทั้งปี |
| PC2 บวกช่วง ก.พ.–เม.ย. และลบช่วง ต.ค.–ธ.ค. | "ช่วงเวลาของ peak" แยกภาคเหนือ (peak หน้าแล้งตอนปลาย) กับภาคกลาง (peak ต้นหนาว) |

> **ข้อควรระวัง:** เครื่องหมายของ PC สลับได้ (คูณ −1 แล้วยังเป็นคำตอบเดียวกัน) อย่าตีความว่า "บวก = ดี" ให้ตีความ *การตรงข้ามกัน* ของเดือนต่าง ๆ แทน และ PC เป็นผลรวมเชิงเส้นทางคณิตศาสตร์ ชื่อที่เราตั้งให้เป็นการตีความของเราเอง

### UMAP (เสริม)

**UMAP** ลดมิติแบบไม่เชิงเส้น เห็นกลุ่มย่อยได้ดีกว่า PCA แต่ระยะห่างระหว่างกลุ่มในกราฟ UMAP *ไม่มีความหมายเชิงปริมาณ* และผลเปลี่ยนตาม `n_neighbors` จึงใช้เพื่อสำรวจ ไม่ใช่เพื่อสรุป

```python
import umap   # แพ็กเกจ umap-learn
emb = umap.UMAP(n_neighbors=10, random_state=42).fit_transform(X)
```

## 4. KMeans: จัดกลุ่มสถานี

**KMeans** แบ่งข้อมูลเป็น k กลุ่ม โดยให้แต่ละจุดอยู่ใกล้จุดศูนย์กลาง (centroid) ของกลุ่มมากที่สุด ต้องกำหนด k เอง

```python
from sklearn.cluster import KMeans
from sklearn.metrics import silhouette_score

for k in range(2, 8):
    km = KMeans(n_clusters=k, n_init=10, random_state=42).fit(X)
    print(k, round(km.inertia_, 1), round(silhouette_score(X, km.labels_), 3))
```

### การเลือก k

| เกณฑ์ | ดูอย่างไร | ข้อจำกัด |
|---|---|---|
| Elbow (inertia) | จุดที่ inertia ลดลงช้าลงชัดเจน | มักไม่มี "ข้อศอก" ชัด |
| Silhouette score | ค่า −1 ถึง 1 ยิ่งสูงยิ่งแยกกลุ่มชัด | ชอบกลุ่มทรงกลมขนาดใกล้กัน |
| ความหมายเชิงโดเมน | อธิบายแต่ละกลุ่มได้หรือไม่ ใช้ตอบคำถามได้หรือไม่ | ต้องมีความรู้โดเมน |

ให้ใช้ทั้งสามเกณฑ์ร่วมกัน ถ้า silhouette ของ k = 3 กับ k = 4 ใกล้กัน ให้เลือกค่าที่อธิบายได้และมีสมาชิกในกลุ่มพอสมควร (ไม่ใช่กลุ่มที่มี 1 สถานี)

### Cluster เป็นสมมติฐาน ไม่ใช่ความจริง

KMeans *จะ* คืนกลุ่มมาให้เสมอ แม้ข้อมูลไม่มีโครงสร้างกลุ่มเลย ผลลัพธ์ขึ้นกับการ scale, การเติมค่าว่าง, k และ `random_state` ก่อนเขียนว่า "พบ 3 กลุ่ม" ให้ตรวจ

1. **ความเสถียร:** เปลี่ยน `random_state` หรือตัดสถานีออกบางส่วน แล้วกลุ่มยังคล้ายเดิมหรือไม่
2. **ความหมาย:** วาด monthly profile เฉลี่ยของแต่ละกลุ่ม แล้วอธิบายเป็นภาษาคนได้หรือไม่
3. **ข้อมูลภายนอก:** เทียบกับคอลัมน์ `region` ด้วย `pd.crosstab` ถ้ากลุ่มตรงกับภาคเกือบทั้งหมด อาจเป็นเพราะภูมิศาสตร์จริง หรือเพียงเพราะเราสร้างกลุ่มจากสิ่งที่สัมพันธ์กับภาคอยู่แล้ว
4. **ภาษาที่ใช้:** เขียนว่า "สถานีกลุ่ม A *มีแนวโน้ม* peak ช่วง มี.ค." ไม่ใช่ "สถานีกลุ่ม A *คือ* สถานีไฟป่า"

สัปดาห์ที่ 13 เราจะเอากลุ่มนี้ไปวางบนแผนที่ ซึ่งเป็นการตรวจความสมเหตุสมผลอีกชั้นหนึ่ง

## 5. Outlier: ความผิดพลาด หรือเหตุการณ์จริง

**Outlier** คือค่าที่ต่างจากข้อมูลส่วนใหญ่มาก แต่ "ต่างมาก" ไม่ได้แปลว่า "ผิด"

| ประเภท | ตัวอย่างใน PM2.5 | ควรทำอย่างไร |
|---|---|---|
| ความผิดพลาดของข้อมูล (error) | ค่าติดลบ, 999 ที่เป็นรหัสแทนค่าว่าง, ค่าเดิมซ้ำ 48 ชั่วโมง, ค่ากระโดด 1 ชั่วโมงแล้วกลับปกติ | แก้ตามกฎที่บันทึกไว้ (สัปดาห์ที่ 6) หรือแปลงเป็น missing พร้อมเหตุผล |
| เหตุการณ์สุดขั้วจริง (real extreme) | ไฟป่าภาคเหนือเดือน มี.ค.–เม.ย., การเผาในที่โล่ง, หมอกควันข้ามแดน | **เก็บไว้** นี่มักเป็นสิ่งที่คำถามของเราสนใจที่สุด |
| ไม่แน่ใจ | สถานีเดียวสูงมากแต่สถานีใกล้เคียงปกติ | ติดธงไว้ ตรวจต่อ และรายงานทั้งแบบรวมและไม่รวม |

### อย่าลบ outlier อัตโนมัติ

คำสั่งแบบ `df = df[df.z.abs() < 3]` อันตรายมากกับข้อมูลคุณภาพอากาศ เพราะจะลบวันที่อากาศแย่ที่สุดซึ่งเป็นวันที่สำคัญต่อสุขภาพที่สุด ทำให้ค่าเฉลี่ยต่ำเกินจริงและซ่อนปัญหา ให้ใช้หลัก

1. **ตรวจจับ** ด้วยวิธีทางสถิติ
2. **ติดธง** เป็นคอลัมน์ใหม่ เช่น `is_outlier`, `outlier_reason`
3. **ตรวจบริบท** เช่น สถานีอื่นในจังหวัดเดียวกันสูงพร้อมกันหรือไม่ อยู่ในฤดูเผาหรือไม่ (ตรวจกับข้อมูลจุดความร้อน เช่น NASA FIRMS ได้ถ้าสนใจ)
4. **ตัดสินใจและบันทึก** ว่าจะเก็บ แก้ หรือแยกวิเคราะห์ พร้อมเหตุผล

### วิธีตรวจจับ

ต้องเทียบกับ "ปกติของบริบทนั้น" ถ้าเทียบกับค่ากลางทั้งปี ทุกวันในหน้าเผาจะกลายเป็น outlier หมด จึงควรเทียบกับเดือนเดียวกันของสถานีเดียวกัน หรือใช้ residual จาก STL (สัปดาห์ที่ 11)

| วิธี | สูตร / แนวคิด | เหมาะกับ |
|---|---|---|
| IQR | นอกช่วง Q1 − 1.5·IQR ถึง Q3 + 1.5·IQR | ภาพรวมเร็ว ๆ (boxplot) |
| Robust z-score (MAD) | 0.6745·(x − median)/MAD เกิน 3.5 | ข้อมูลเบ้ ทนต่อ outlier เองมากกว่า z-score ปกติ |
| STL residual | residual ที่ใหญ่ผิดปกติหลังตัด trend/seasonality | time series รายสถานี |
| Isolation Forest (PyOD, เสริม) | จุดที่ถูก "แยกออก" ได้ง่ายในหลายมิติ | ดูหลายมลพิษพร้อมกัน เช่น PM2.5 สูงแต่ PM10 ต่ำผิดธรรมชาติ |

```python
d = con.sql("SELECT station_id, date, pm25_mean FROM daily_pm25_clean WHERE is_complete").df()
d["month"] = pd.to_datetime(d["date"]).dt.month
d["log_pm25"] = np.log(d["pm25_mean"])          # สเกล log เพราะค่า PM2.5 เบ้ขวา
g = d.groupby(["station_id", "month"])["log_pm25"]
med = g.transform("median")
mad = g.transform(lambda s: (s - s.median()).abs().median())
d["robust_z"] = 0.6745 * (d["log_pm25"] - med) / mad
d["is_outlier"] = d["robust_z"].abs() > 3.5
```

คำนวณในสเกล log เพราะในสเกลเดิม การกระจายของเดือนที่ค่าสูงกว้างกว่าเดือนที่ค่าต่ำมาก วันที่สูงผิดปกติในฤดูฝนจึงถูกมองข้าม ส่วนการตัดสินว่าธงใดเป็นความผิดพลาดหรือเหตุการณ์จริง ให้เทียบกับ *สถานีอื่น* ในจังหวัดเดียวกันในวันเดียวกัน (คู่มือปฏิบัติการขั้นที่ 5 และหนังสือบทที่ 15)

## 6. PDPA กับโครงการข้อมูล

### ข้อมูลส่วนบุคคลคืออะไร

**พระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (PDPA)** บังคับใช้เต็มรูปแบบตั้งแต่ 1 มิถุนายน 2565 นิยาม **ข้อมูลส่วนบุคคล** ว่าเป็นข้อมูลเกี่ยวกับบุคคลที่ทำให้ระบุตัวบุคคลนั้นได้ *ไม่ว่าทางตรงหรือทางอ้อม* (ไม่รวมข้อมูลของผู้ถึงแก่กรรม)

| ประเภท | ตัวอย่าง |
|---|---|
| ระบุตัวตรง | ชื่อ–นามสกุล, เลขประจำตัวประชาชน, เบอร์โทร, อีเมล, HN โรงพยาบาล |
| ระบุตัวทางอ้อม (quasi-identifier) | อายุ + เพศ + ตำบล + วันที่เข้ารับบริการ รวมกัน |
| ข้อมูลอ่อนไหว (มาตรา 26) | ข้อมูลสุขภาพ, ความพิการ, พันธุกรรม, ชีวภาพ, ศาสนา, ประวัติอาชญากรรม ฯลฯ ต้องได้รับความยินยอมโดยชัดแจ้ง เว้นแต่เข้าข้อยกเว้นตามกฎหมาย |

ข้อมูล PM2.5 รายสถานีไม่ใช่ข้อมูลส่วนบุคคล แต่ถ้าโครงการต่อยอดเป็น *"PM2.5 กับจำนวนผู้ป่วยโรคทางเดินหายใจ"* แล้วใช้ข้อมูลการเข้ารับบริการรายคน ข้อมูลนั้นเป็น **ข้อมูลสุขภาพซึ่งเป็นข้อมูลอ่อนไหว** แม้ตัดชื่อออกแล้ว ถ้ายังมีอายุ เพศ ที่อยู่ระดับตำบล และวันที่ ก็อาจระบุตัวได้ในชุมชนเล็ก ๆ

> **หลักของรายวิชา:** ห้ามนำข้อมูลส่วนบุคคลจริงเข้า repo หรือเครื่องส่วนตัวโดยไม่มีการอนุญาต ถ้าโครงการต้องใช้ข้อมูลระดับบุคคลจริง ต้องผ่านผู้สอนและคณะกรรมการจริยธรรมการวิจัยในมนุษย์ก่อน ระหว่างพัฒนาให้ใช้ **ข้อมูลสังเคราะห์** หรือ **ข้อมูลรวม (aggregate)** เช่น จำนวนผู้ป่วยต่อจังหวัดต่อสัปดาห์จากรายงานที่เผยแพร่ (เนื้อหาส่วนนี้เป็นแนวทางทางวิชาการ ไม่ใช่คำปรึกษาทางกฎหมาย)

### Anonymization กับ pseudonymization

| | Pseudonymization (แฝงข้อมูล) | Anonymization (ทำให้นิรนาม) |
|---|---|---|
| ทำอะไร | แทนตัวระบุด้วยรหัส เช่น HN → `P0001` โดยมีตารางจับคู่หรือกุญแจเก็บแยก | ทำให้ระบุตัวไม่ได้อีก ไม่ว่าด้วยวิธีที่สมเหตุสมผลใด |
| ย้อนกลับได้ไหม | ได้ ถ้ามีกุญแจ | ไม่ควรย้อนกลับได้ |
| ยังเป็นข้อมูลส่วนบุคคลไหม | **ยังเป็น** อยู่ภายใต้ PDPA | ถ้าทำได้จริง ไม่อยู่ภายใต้ PDPA |
| เทคนิค | hash พร้อม secret key, รหัสสุ่ม | รวมกลุ่ม (aggregate), generalize อายุเป็นช่วง/ที่อยู่เป็นจังหวัด, ตัดกลุ่มที่มีคนน้อย |

### ความเสี่ยง re-identification

การลบชื่อออกไม่พอ งานวิจัยของ Latanya Sweeney พบว่า รหัสไปรษณีย์ + เพศ + วันเกิด ระบุตัวชาวอเมริกันได้ราว 87% ความเสี่ยงสูงขึ้นเมื่อ

- ข้อมูลละเอียดมาก (วันที่แน่นอน, ระดับตำบล) หรือมีกลุ่มที่มีคนน้อย (เช่น "ผู้ป่วยอายุ 90+ ในตำบลหนึ่ง" มี 1 คน)
- นำไปเชื่อมกับข้อมูลภายนอก (social media, ข่าว)

แนวคิด **k-anonymity** กำหนดว่าทุกชุดค่าของ quasi-identifier ต้องมีอย่างน้อย k คน เช่น k = 5 แนวปฏิบัติทั่วไปในการรายงานคือไม่แสดงช่องที่นับได้น้อยกว่า 5–10

## 7. ข้อมูลสังเคราะห์ (synthetic data)

| เครื่องมือ | ใช้ทำอะไร | รักษาสถิติของข้อมูลจริง | ความเสี่ยงด้านความเป็นส่วนตัว |
|---|---|---|---|
| **Faker** (หลัก) | สร้างข้อมูลปลอมรูปแบบสมจริง เพื่อทดสอบโค้ด schema และ pipeline | ไม่ (สุ่มอิสระ) | ต่ำมาก ไม่ได้เรียนจากข้อมูลจริง |
| **SDV** (เสริม) | เรียนการแจกแจงจากตารางจริง แล้วสร้างตารางใหม่ที่สถิติคล้ายเดิม | ใช่ บางส่วน | **ไม่ได้ปลอดภัยอัตโนมัติ** |
| **SMOTE** (เสริม) | เพิ่มตัวอย่างกลุ่มน้อยใน classification | ไม่ใช่เป้าหมาย | — |

### Faker: ข้อมูลปลอมสำหรับทดสอบ pipeline

สมมติว่าอนาคตจะได้ตารางผู้ป่วยจากโรงพยาบาล เราสร้าง *ตารางปลอมที่มี schema เดียวกัน* เพื่อเขียนและทดสอบโค้ดเชื่อมกับ `daily_pm25_clean` ได้ตั้งแต่วันนี้ โดยไม่แตะข้อมูลจริง

```python
from faker import Faker

Faker.seed(42)
fake = Faker("th_TH")
print(fake.name(), "|", fake.date_between(start_date="-1y", end_date="today"))
```

ชื่อที่ได้เป็นชื่อไทยที่ไม่มีอยู่จริง แต่จำนวนผู้ป่วยที่สุ่มขึ้นไม่สัมพันธ์กับ PM2.5 จึง **ห้ามนำผลวิเคราะห์จากข้อมูล Faker ไปสรุป** ใช้ได้แค่ตรวจว่าโค้ดทำงานถูก

### SDV: ข้อมูลสังเคราะห์ที่รักษาสถิติ (เสริม)

```python
from sdv.metadata import Metadata
from sdv.single_table import GaussianCopulaSynthesizer

data = {"visits": real_df}                       # SDV 2.x รับข้อมูลเป็น dict ของตาราง
metadata = Metadata.detect_from_dataframes(data)
synth = GaussianCopulaSynthesizer(metadata)
synth.fit(data)
synthetic = synth.sample(num_rows=1000)["visits"]
```

API ของ SDV เปลี่ยนบ่อย ตัวอย่างนี้ใช้ SDV 2.0 ส่วนรุ่น 1.x รับ DataFrame โดยตรงและใช้ `Metadata.detect_from_dataframe` ให้ตรวจ `sdv.__version__` ก่อนเสมอ

ขีดจำกัดที่ต้องรู้

- **ไม่ได้เป็นส่วนตัวโดยอัตโนมัติ** โมเดลอาจจำและสร้างแถวที่เหมือนหรือเกือบเหมือนคนจริงที่หายาก (outlier) ได้ ถ้าจะเผยแพร่ต้องตรวจความใกล้เคียงกับแถวจริง หรือใช้เทคนิค differential privacy ซึ่งอยู่นอกขอบเขตรายวิชา
- การ fit ต้องใช้ข้อมูลจริง จึงยังต้องได้รับอนุญาตให้เข้าถึงข้อมูลจริงก่อน
- รักษาสถิติได้บางส่วน ความสัมพันธ์ที่ซับซ้อนหรือหายากอาจหายไป ข้อค้นพบสุดท้ายต้องยืนยันกับข้อมูลจริงเสมอ

### SMOTE (เสริม, กล่าวถึงโดยย่อ)

ถ้าภายหลังสร้างโมเดลทำนาย "วันอากาศอันตราย" ซึ่งมีน้อยกว่าวันปกติมาก (imbalanced classes) **SMOTE** (`imblearn.over_sampling.SMOTE`) สร้างตัวอย่างกลุ่มน้อยเพิ่มโดยประมาณค่าระหว่างจุดที่ใกล้กัน ใช้กับ *training set เท่านั้น* หลังแบ่ง train/test แล้ว และไม่ใช่เครื่องมือปกป้องความเป็นส่วนตัว

## สรุป

- ข้อมูลหลายมิติต้อง scale ก่อน เพราะ PCA และ KMeans อ่อนไหวต่อขนาดของตัวแปร
- PCA ใช้ลดมิติ ตีความผ่าน explained variance และ loadings โดยไม่ยึดติดกับเครื่องหมาย
- เลือก k ด้วย silhouette + elbow + ความหมายเชิงโดเมน และถือว่า cluster เป็นสมมติฐานที่ต้องตรวจต่อ
- outlier อาจเป็น error หรือเหตุการณ์จริง ให้ตรวจจับ ติดธง ตรวจบริบท แล้วตัดสินใจพร้อมบันทึก อย่าลบอัตโนมัติ
- ข้อมูลสุขภาพรายบุคคลเป็นข้อมูลอ่อนไหวตาม PDPA, pseudonymized data ยังเป็นข้อมูลส่วนบุคคล และการลบชื่ออย่างเดียวไม่พอ
- Faker ใช้ทดสอบ pipeline, SDV รักษาสถิติได้บางส่วนแต่ไม่ได้เป็นส่วนตัวอัตโนมัติ

## คำถามทบทวน

1. ถ้าไม่ scale ก่อนทำ KMeans กับเมทริกซ์สถานี × เดือน กลุ่มที่ได้จะถูกกำหนดโดยเดือนใดมากที่สุด เพราะอะไร
2. PC1 มี loadings เป็นบวกทุกเดือน ส่วน PC2 บวกช่วง ก.พ.–เม.ย. และลบช่วง ต.ค.–ธ.ค. สถานีที่มี PC2 สูงมีลักษณะอย่างไร
3. silhouette score ของ k = 2 สูงที่สุด แต่ k = 4 อธิบายเชิงโดเมนได้ดีกว่า จะเลือกอย่างไรและเขียนเหตุผลอย่างไร
4. วันที่ 15 มี.ค. สถานีในเชียงใหม่ 5 แห่งมี PM2.5 สูงกว่า 150 µg/m³ พร้อมกัน ควรจัดเป็น outlier ประเภทใด และควรทำอย่างไรกับค่าเหล่านี้
5. ตารางผู้ป่วยที่แทน HN ด้วยรหัสสุ่มแต่ยังมีอายุ เพศ ตำบล และวันที่รับบริการ เป็นข้อมูล anonymized หรือไม่ เพราะอะไร
6. ทำไมข้อมูลที่สร้างด้วย SDV จึงยังอาจมีความเสี่ยงด้านความเป็นส่วนตัว
