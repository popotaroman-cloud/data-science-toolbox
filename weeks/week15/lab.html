ขั้นที่ 1: ตรวจความพร้อมของ repo (Checklist ก่อนส่งงาน)

ระบบ

เอกสาร

ความปลอดภัยและ PDPA

git ls-files | grep -iE "\.duckdb|\.parquet|\.csv|\.env$|\.geojson"   # ควรไม่มีผลลัพธ์

git grep -nE "[A-Za-z]:\\\\|/Users/|/home/"                             # ไม่มี path absolute

ถ้าพบไฟล์ความลับในประวัติ commit ให้ เปลี่ยน key ทันที แล้วแจ้งผู้สอน (ทบทวนสัปดาห์ที่ 1)

ขั้นที่ 2: ซ้อมนำเสนอแบบจับเวลา

ซ้อมกับเพื่อนในกลุ่ม 3 คน ผลัดกันเป็น ผู้นำเสนอ ผู้จับเวลา และ ผู้ถาม

  1. ผู้นำเสนอพูดตามลำดับในคู่มือ (10 นาที) ผู้จับเวลาบอกเมื่อถึงนาทีที่ 5, 8 และ 10
  2. ผู้ถามเลือกคำถาม 2 ข้อจากตารางตัวอย่างคำถามในคู่มือ และขอให้อธิบายโค้ด 1 ฟังก์ชันที่ชี้แบบสุ่ม
  3. จดผลซ้อมตามตารางนี้ แล้วปรับก่อนวันจริง
ประเด็น ผลซ้อม สิ่งที่จะแก้
เวลาที่ใช้จริง … นาที
ข้อค้นพบหลักชัดใน 1 นาทีแรกหรือไม่
demo ติดขัดตรงไหน
คำถามที่ตอบไม่ได้ / ตอบไม่มั่นใจ
โค้ดส่วนที่ต้องทบทวน

เตรียมแผนสำรอง: ภาพหน้าจอแดชบอร์ดแต่ละระดับ และ report.html ที่เปิดได้แบบ offline

ขั้นที่ 3: Fresh-clone + run dashboard test ให้เพื่อน

ทำ ก่อนวันนำเสนออย่างน้อย 2 วัน เพื่อให้เจ้าของ repo มีเวลาแก้ ผู้ทดสอบทำตาม README ของเพื่อนเท่านั้น ห้ามแก้ไฟล์เอง และห้ามเจ้าของช่วยพูด

git clone https://github.com/<เพื่อน>/<repo>.git final-test
cd final-test
git checkout main
# ทำตาม README ทุกขั้น: สร้าง env → run_all.py (หรือไฟล์ตัวอย่างจากผู้สอน) → render รายงาน → เปิด app

ขั้นที่ 4: ติด tag v1.0 และส่งงาน

เมื่อทุกข้อในขั้นที่ 1 ผ่านและ issue ปิดแล้ว

git switch main && git pull
git tag -a v1.0 -m "โครงการสุดท้าย: ส่งเพื่อนำเสนอ"
git push origin v1.0

ส่งในระบบส่งงานของรายวิชา: ลิงก์ repo, ลิงก์ tag v1.0, ลิงก์ issue ที่ตนเองเปิดให้เพื่อน และไฟล์ report.html

ถ้าต้องแก้หลังติด tag ก่อนกำหนดส่ง ให้สร้าง tag ใหม่ v1.1 แทนการลบ tag เดิม และแจ้งผู้สอน

อาการ สาเหตุและวิธีแก้
fresh clone สร้าง environment ไม่ได้บนเครื่องเพื่อน ไลบรารีบางตัวไม่มีใน channel หรือ pin เวอร์ชันที่ผูกกับ OS ใช้ conda env export --from-history แล้วตรวจด้วยมือ หรือลด pin ให้เหลือเวอร์ชันหลัก
run_all.py ล่มเพราะ API ไม่ตอบ README ต้องมีทางเลือกใช้ไฟล์ตัวอย่างจากผู้สอน และ script ควรแจ้ง error ที่อ่านเข้าใจได้
แดชบอร์ดช้ามากในวัน demo query ไม่ได้อยู่ใน st.cache_data หรือ query จาก measurements รายชั่วโมงทุกครั้ง ใช้ daily_pm25_clean และสรุปล่วงหน้า
เปิด app แล้ว IOException เรื่อง lock มี notebook หรือ script ที่เปิดฐานข้อมูลแบบเขียนได้ค้างอยู่ ปิด kernel ทั้งหมดก่อน demo
git push origin v1.0 ถูกปฏิเสธเพราะ tag มีอยู่แล้ว อย่าบังคับเขียนทับ ให้สร้าง v1.1 และแจ้งผู้สอน
ตัวเลขในรายงานกับแดชบอร์ดไม่ตรงกัน ใช้ช่วงวันที่หรือวิธีเฉลี่ยต่างกัน ย้าย query ร่วมไปไว้ใน src/queries.py และระบุช่วงวันที่ในทั้งสองที่
