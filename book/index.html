คำนำ

หนังสือเล่มนี้เขียนขึ้นเพื่อประกอบการสอนรายวิชา 1145100 ชุดเครื่องมือสำหรับวิทยาการข้อมูล (Data Science Toolbox) หลักสูตรวิทยาศาสตรบัณฑิต สาขาวิชาวิทยาการข้อมูลและนวัตกรรมซอฟต์แวร์ มหาวิทยาลัยอุบลราชธานี รายวิชานี้มีเอกสารประกอบการสอนและคู่มือปฏิบัติการรายสัปดาห์อยู่แล้ว เอกสารเหล่านั้นตอบคำถามว่า ทำอย่างไร หนังสือเล่มนี้ตอบเพิ่มว่า ทำไม และ ลึกลงไปเป็นอย่างไร

เครื่องมือด้านข้อมูลเปลี่ยนเร็ว ไลบรารีที่นิยมในวันนี้อาจถูกแทนที่ภายในไม่กี่ปี แต่คำถามที่เครื่องมือเหล่านั้นพยายามตอบเปลี่ยนช้ากว่ามาก ข้อมูลนี้มาจากไหน วัดอะไร หายไปตรงไหน การแจกแจงเป็นอย่างไร ความต่างที่เห็นมากกว่าความผันผวนโดยบังเอิญหรือไม่ และจะบอกผู้อ่านอย่างไรให้เข้าใจถูกต้อง หนังสือเล่มนี้จึงสอนเครื่องมือควบคู่กับแนวคิดที่อยู่เบื้องหลัง เพื่อให้ผู้อ่านเปลี่ยนเครื่องมือได้เมื่อถึงเวลา โดยไม่ต้องเริ่มคิดใหม่ทั้งหมด

ทั้งเล่มใช้กรณีศึกษาเดียว คือ ระบบสำรวจคุณภาพอากาศ PM2.5 ของประเทศไทย ตั้งแต่การดึงข้อมูลจาก API ของ Air4Thai การจัดเก็บใน DuckDB การตรวจคุณภาพและจัดการข้อมูลสูญหาย การสำรวจด้วยภาพ สถิติ อนุกรมเวลา การวิเคราะห์หลายมิติและเชิงพื้นที่ ไปจนถึงรายงาน Quarto และแดชบอร์ด Streamlit ผู้อ่านจะเห็นว่าการตัดสินใจในขั้นต้น เช่น เกณฑ์ความครบถ้วนของข้อมูลรายวัน ส่งผลต่อข้อสรุปในขั้นท้ายอย่างไร ซึ่งเป็นสิ่งที่ตัวอย่างแยกเป็นชิ้น ๆ แสดงไม่ได้ ภาพรวมของเล่ม เส้นทางการอ่าน และความสัมพันธ์กับแผนการสอนอยู่ในบทที่ 0 (0.9)

ผู้อ่านที่คาดหวัง

ผู้อ่านหลักคือนักศึกษาที่เรียน Python เบื้องต้นและสถิติเบื้องต้นมาแล้ว ไม่จำเป็นต้องรู้ SQL หรือเคยใช้ Git มาก่อน ผู้อ่านกลุ่มอื่นที่น่าจะได้ประโยชน์ ได้แก่ ผู้สอนรายวิชาที่ใกล้เคียงกัน นักวิเคราะห์ข้อมูลในหน่วยงานที่ต้องการวางระบบให้ทำซ้ำได้ และผู้ที่ใช้เครื่องมือคล่องแล้วแต่ต้องการพื้นฐานด้านคุณภาพข้อมูล การตั้งคำถาม และการตีความผล ความรู้พื้นฐานที่ควรมีก่อนอ่านอธิบายไว้ใน 0.8

เกี่ยวกับข้อมูลและตัวอย่างในเล่ม

ข้อมูลคุณภาพอากาศของประเทศไทยเป็นของกรมควบคุมมลพิษ เผยแพร่ผ่าน Air4Thai (ง.1) ผู้เขียนขอขอบคุณหน่วยงานที่เปิดเผยข้อมูลนี้ให้สาธารณะใช้ได้

ผลลัพธ์ตัวอย่างและรูปประกอบในหลายบทมาจาก ข้อมูลสมมุติ ที่ผู้เขียนกำหนดเพื่อแสดงรูปแบบของผลลัพธ์ หรือ ข้อมูลสังเคราะห์ ที่สร้างด้วยโปรแกรมให้มีรูปแบบคล้ายข้อมูลจริง ได้แก่ ฤดูฝุ่นช่วงต้นปี ความต่างระหว่างภาค ช่วงที่เซนเซอร์ดับ และค่าผิดปกติ ทุกบทระบุไว้ที่ผลลัพธ์หรือ caption ของรูปทุกครั้ง และรายละเอียดอยู่ใน ง.6 ตัวเลขเหล่านั้นจึงใช้แสดงวิธีการและวิธีอ่านผล ไม่ใช่ข้อค้นพบเกี่ยวกับคุณภาพอากาศจริงของประเทศไทย เมื่อผู้อ่านรันโค้ดกับข้อมูลที่ดึงมาเอง ตัวเลขจะต่างออกไป แต่รูปแบบการวิเคราะห์และการตีความใช้ได้เหมือนเดิม ข้อเท็จจริงที่ไม่ได้มาจากข้อมูลตัวอย่าง เช่น ค่ามาตรฐานคุณภาพอากาศและเกณฑ์ดัชนีคุณภาพอากาศ อ้างอิงจากแหล่งทางการและระบุเวลาที่ตรวจสอบไว้

สัญลักษณ์และข้อตกลงในการเขียน

สัญลักษณ์และองค์ประกอบของแต่ละบท ได้แก่ ★ เนื้อหาเชิงลึก กล่องข้อความสี่แบบ และแบบฝึกหัดสามระดับ อธิบายไว้ใน 0.9 ข้อตกลงเพิ่มเติมมีดังนี้

โค้ดในเล่มเขียนตาม PEP 8 (ก.8) และแสดงเฉพาะส่วนที่เกี่ยวกับหัวข้อ เมื่อโค้ดยาวเกินกว่าจะแสดงในหน้าเดียว จะแบ่งเป็นช่วงพร้อมคำอธิบาย โค้ดฉบับเต็มของระบบที่สร้างตลอดเล่มอยู่ในบทที่ 21

สร้างสภาพแวดล้อม

ดาวน์โหลด repository ของรายวิชา แล้วสร้างสภาพแวดล้อมจากไฟล์ที่ให้มา ไฟล์ environment.yml (สำหรับ conda) และ pyproject.toml (สำหรับ uv) ระบุไลบรารีทั้งหมดที่ใช้ในเล่ม

git clone https://github.com/popotaroman-cloud/data-science-toolbox.git
cd data-science-toolbox

# ทางเลือกที่ 1: conda
conda env create -f environment.yml
conda activate dstoolbox

# ทางเลือกที่ 2: uv
uv sync
source .venv/bin/activate          # Windows: .venv\Scripts\activate

ตรวจว่าติดตั้งครบด้วยคำสั่งต่อไปนี้ ถ้ามีไลบรารีใดแสดงข้อผิดพลาด ให้ดูภาคผนวก ฉ (ฉ.1)

import importlib

for name in ["duckdb", "pandas", "polars", "pandera", "seaborn", "plotly",
             "scipy", "statsmodels", "sklearn", "geopandas", "streamlit"]:
    module = importlib.import_module(name)
    print(f"{name:12s} {module.__version__}")

ชุดข้อมูลของโครงการ

ผู้อ่านสร้างฐานข้อมูลของโครงการเองทีละขั้นตามบทที่ 5 ถึง 10 ได้แก่ ดึงข้อมูลจาก Air4Thai (บทที่ 5) โหลดเข้า DuckDB (บทที่ 6–7) สร้างตารางรายวัน (บทที่ 8) ตรวจคุณภาพ (บทที่ 9) และจัดการข้อมูลสูญหายจนได้ตาราง daily_pm25_clean (บทที่ 10) ซึ่งเป็นตารางหลักของการวิเคราะห์ตั้งแต่บทที่ 11 เป็นต้นไป โครงสร้างของทุกตารางสรุปไว้ใน 0.6

ผู้อ่านที่ต้องการเริ่มจากบทหลัง ๆ หรือเข้าถึง API ไม่ได้ เช่น เพราะปัญหาเครือข่าย ให้ใช้ไฟล์ข้อมูลตัวอย่างที่ผู้สอนแจกในชั้นเรียน ซึ่งมีโครงสร้างตารางเดียวกัน รายชื่อไฟล์และบทที่ใช้อยู่ใน ง.6 ไฟล์ข้อมูลทั้งหมดอยู่ในโฟลเดอร์ data/ ซึ่งไม่ถูก commit เข้า Git (โครงสร้างโครงการ การตั้งค่า และการจัดการความลับ (.env)) เพราะสร้างใหม่ได้จาก script และอาจมีขนาดใหญ่
