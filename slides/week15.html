ส่วน สิ่งที่ต้องแสดง CLO

ลำดับและเวลา

15 นาทีต่อคน · ผู้สอนหยุดเมื่อครบเวลา

นาที ส่วน
0–1 โจทย์ คำถาม และข้อค้นพบหลัก 1 ประโยค
1–5 Demo end-to-end + drill-down บนแดชบอร์ดสด
5–8 คำตอบของคำถาม + คุณภาพข้อมูลที่กระทบคำตอบ
8–10 ข้อจำกัด, PDPA/จริยธรรม, สะท้อนการใช้ AI
10–15 ถามตอบ (ผู้สอนและเพื่อน)

ข้อแนะนำด้านเทคนิค

  • ใช้ ฐานข้อมูลที่สร้างไว้ล่วงหน้า · แสดง log การรัน run_all.py ล่าสุดแทนได้
  • เปิดแดชบอร์ด, รายงาน HTML และ GitHub repo ไว้ล่วงหน้าคนละแท็บ
  • เตรียม ภาพหน้าจอสำรอง แต่ demo สดได้คะแนนเต็มกว่า
  • ปิด notebook / kernel ที่เปิดฐานข้อมูลแบบเขียนได้ก่อน demo (กัน IOException เรื่อง lock)
  • สไลด์ไม่บังคับ: ไม่เกิน 6–8 หน้า หรือใช้รายงาน Quarto เป็นสื่อ

ช่วงถามตอบ

ผู้สอนเลือกโค้ด ส่วนใดก็ได้ ให้อธิบาย

อธิบายไม่ได้ = ส่วนนั้นไม่ใช่ผลงานของตนเอง (ตามนโยบาย AI)

หมวด ตัวอย่างคำถาม
Pipeline ถ้า Air4Thai เปลี่ยนชื่อ field ใน JSON ระบบจะพังที่ไหน รู้ได้อย่างไร
DuckDB ข้อมูลรายวันที่ทำความสะอาดแล้วคำนวณอย่างไร วันที่ไม่ครบ 24 ชั่วโมงจัดการอย่างไร
คุณภาพข้อมูล เลือกวิธีจัดการค่าหายนี้เพราะเชื่อว่าเป็น MCAR, MAR หรือ MNAR
การวิเคราะห์ ข้อค้นพบนี้เป็นความสัมพันธ์หรือเหตุและผล มีตัวแปรแฝงอะไรได้บ้าง

ตัวอย่างคำถาม (ต่อ)

หมวด ตัวอย่างคำถาม
แดชบอร์ด ทำไมใช้ st.cache_resource กับ connection แต่ st.cache_data กับ query
Reproducibility ถ้าเพื่อน clone repo วันนี้ ต้องทำกี่ขั้นจึงเห็นแดชบอร์ด
PDPA ถ้าได้ข้อมูลผู้ป่วยรายคนจากโรงพยาบาล จะออกแบบระบบใหม่อย่างไร
AI ยกตัวอย่างโค้ดที่ AI เขียนผิดและวิธีที่ตรวจพบ

ระบบและข้อมูล (CLO1–CLO3)

CLO เกณฑ์ คะแนน ดีเยี่ยม (เต็ม)
CLO1 Environment, Git workflow, reproducibility 4 fresh clone ผ่านตาม README โดยไม่ต้องช่วย · PR + review ต่อเนื่อง · commit message สื่อความหมาย

การวิเคราะห์และการสื่อสาร (CLO4–CLO6)

CLO เกณฑ์ คะแนน ดีเยี่ยม (เต็ม)
CLO4 สำรวจด้วยภาพและสถิติเพื่อตอบคำถาม 6 ตอบทุกคำถามด้วยภาพ + สถิติ · เทคนิคเหมาะ · ภาษาตรงระดับความมั่นใจ
CLO5 แดชบอร์ด 4 drill-down 4 ระดับลื่นไหล · ตัวกรองทุกระดับ · read-only + cache ถูกต้อง
CLO5 การนำเสนอและถามตอบ 3 ข้อค้นพบก่อน · ตรงเวลา · demo สด · อธิบายโค้ดได้ทั้งหมด
CLO6 จริยธรรม PDPA และการใช้ AI 4 PDPA เฉพาะโครงการ · สัญญาอนุญาต · AI_USAGE.md ละเอียดพร้อมตัวอย่างข้อผิดพลาด

สิ่งที่ทำให้เสียคะแนนมาก

  • รันจาก fresh clone ไม่ได้ หรือ commit ใหญ่ครั้งเดียวท้ายภาค (CLO1)
  • ข้อมูลดาวน์โหลดด้วยมือครั้งเดียว หรือ pipeline ไม่ทำงาน (CLO2)
  • ลบ/เติมค่าโดยไม่มีเหตุผล (CLO3)
  • กราฟสวยแต่ไม่ตอบคำถาม หรือสรุปเกินหลักฐาน (CLO4)
  • อธิบายโค้ดของตนเองไม่ได้ (CLO5)
  • พบข้อมูลส่วนบุคคล/ความลับใน repo (CLO6)

เงื่อนไขขั้นต่ำ

  1. ผ่าน fresh-clone test จากเพื่อน (issue ผลการทดสอบปิดแล้ว)
  2. ไม่มีข้อมูล ความลับ (.env, API key) หรือข้อมูลส่วนบุคคล ทั้งใน repo และประวัติ commit
  3. ทุก PR สัปดาห์ที่ 1–14 ถูก merge หรือปิดพร้อมเหตุผล · main รันได้
  4. README ระบุแหล่งข้อมูล สัญญาอนุญาต และวันที่ดึงข้อมูลชุดที่ใช้นำเสนอ

ความซื่อสัตย์ทางวิชาการ

  • ใช้ AI ช่วยเขียนโค้ดได้เสมอ แต่ต้อง บันทึก ใน AI_USAGE.md และ อธิบายได้
  • ใช้โค้ด/แนวคิดจากเพื่อนหรือแหล่งภายนอก → อ้างอิงใน README หรือ comment
  • ปกปิดว่าส่วนใดไม่ทำงาน แย่กว่า บอกตรง ๆ พร้อมแผนแก้ไข
  • รายงานข้อจำกัดอย่างซื่อตรงได้คะแนนใน CLO4 และ CLO6

ปฏิบัติการ

งานสัปดาห์นี้

  1. ตรวจความพร้อมของ repo ตาม checklist บน main
  2. ซ้อมนำเสนอจับเวลา กลุ่ม 3 คน: ผู้นำเสนอ / ผู้จับเวลา (นาที 5, 8, 10) / ผู้ถาม
  3. Fresh-clone + run dashboard test ให้เพื่อน ก่อนวันนำเสนอ ≥ 2 วัน → issue Final fresh-clone test
  4. แก้ตาม issue (fixes #N) → ติด tag v1.0 → ส่งงาน
  5. วันนำเสนอ: ประเมินเพื่อนอย่างน้อย 3 คน
  6. หลังนำเสนอ: commit REFLECTION.md

แบบประเมินเพื่อน (คะแนน 1–4 ต่อหัวข้อ)

  • คำถามชัด ข้อค้นพบเข้าใจใน 1 นาทีแรก · หลักฐานสนับสนุนจริง · demo ครบ end-to-end
  • ข้อจำกัด/PDPA ตรงไปตรงมา · อธิบายการใช้ AI ชัด · ตอบคำถามตรงประเด็น
  • ความคิดเห็นต้อง เจาะจง สร้างสรรค์ วิจารณ์ งาน ไม่ใช่ ตัวบุคคล (“ดีมาก” อย่างเดียวไม่ได้คะแนน)

REFLECTION.md (~1 หน้า): คำถามและคำตอบ · การตัดสินใจสำคัญ 2 ครั้ง · ปัญหาคุณภาพข้อมูล · การใช้ AI · PDPA · ข้อเสนอแนะจากเพื่อน · ทักษะที่ได้

ก่อนวันนำเสนอ

  • เขียนข้อค้นพบที่สำคัญที่สุดให้ได้ใน 1 ประโยค
  • ถ้าต้องตัดเนื้อหาครึ่งหนึ่ง จะเก็บส่วนใดไว้ เพราะอะไร
  • ทบทวนโค้ดส่วนที่ตนเองอธิบายได้ยากที่สุด
  • เตรียมภาพหน้าจอแดชบอร์ดแต่ละระดับ + report.html เปิดแบบ offline

หลังจบรายวิชา: ปรับ README เป็น portfolio · พิจารณา deploy (ตรวจสัญญาอนุญาตและไม่มีข้อมูลส่วนบุคคล) · ต่อยอดคำถามที่ยังตอบไม่ได้
