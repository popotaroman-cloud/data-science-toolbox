1. ข้อมูลสูญหายมีสองหน้าตา

สัปดาห์ที่ 6 เรานับค่า NULL ใน pm25 ไปแล้ว แต่นั่นเป็นเพียงครึ่งเดียว

แบบ ลักษณะ ตัวอย่าง
Explicit missing มีแถว แต่ค่าเป็น NULL สถานีส่งข้อมูลมา แต่ช่อง pm25 ว่าง หรือเป็น sentinel ที่แปลงเป็น NULL แล้ว
Implicit missing ไม่มีแถวนั้นเลย สถานีไม่ส่งข้อมูลช่วง 02:00–05:00 จึงไม่มีแถวของชั่วโมงเหล่านั้นในฐานข้อมูล

isna() มองไม่เห็นแบบที่สอง ต้องสร้าง ตารางเวลาเต็ม (full grid) ทุกสถานี × ทุกชั่วโมงก่อน แล้วนำข้อมูลจริงมาเติม ช่องที่ไม่มีข้อมูลจะกลายเป็น NaN

import duckdb, pandas as pd

con = duckdb.connect("data/pm25.duckdb", read_only=True)
m = con.execute("SELECT station_id, ts, pm25, pm10 FROM measurements").df()
con.close()

start = m["ts"].min().floor("D")
end = m["ts"].max().floor("D") + pd.Timedelta(days=1)   # เริ่มวันถัดไป (ไม่รวม)
hours = pd.date_range(start, end, freq="h", inclusive="left")   # 24 ชั่วโมงต่อวันครบทุกวัน
full_idx = pd.MultiIndex.from_product([m["station_id"].unique(), hours],
                                      names=["station_id", "ts"])
hourly = m.set_index(["station_id", "ts"]).reindex(full_idx).reset_index()

print(f"แถวจริง {len(m):,} · แถวที่ควรมี {len(hourly):,}")
print(f"pm25 ว่างจริง {hourly['pm25'].isna().mean():.1%}")

ตัวเลขที่สองมักสูงกว่าที่เห็นในสัปดาห์ที่ 6 อย่างชัดเจน ขั้นตอนนี้ต้องทำได้เพราะ (station_id, ts) ไม่ซ้ำ ซึ่งเราตรวจด้วย pandera ไปแล้ว

2. กลไกการสูญหาย (Missingness mechanisms)

Rubin (1976) แบ่งกลไกการสูญหายเป็น 3 แบบ ตามคำถามว่า “โอกาสที่ค่าจะหาย ขึ้นกับอะไร”

กลไก ความหมาย ตัวอย่าง PM2.5 ผลถ้าทิ้งค่าที่หาย
MCAR (Missing Completely At Random) โอกาสหายไม่ขึ้นกับอะไรเลย ไฟดับแบบสุ่ม หรือเครือข่ายขัดข้องชั่วคราวไม่เป็นรูปแบบ ไม่เอนเอียง แค่ข้อมูลน้อยลง
MAR (Missing At Random) โอกาสหายขึ้นกับตัวแปรที่ เราเห็น สถานีปิดซ่อมบำรุงตามรอบทุกวันอังคารช่วงกลางวัน หรือสถานีบางแห่งเก่ากว่าจึงเสียบ่อยกว่า เอนเอียงได้ แต่แก้ได้ถ้าคำนึงถึงตัวแปรนั้น (เช่น วิเคราะห์แยกสถานี)
MNAR (Missing Not At Random) โอกาสหายขึ้นกับ ค่าที่หายไปเอง เซนเซอร์อิ่มตัวหรือไส้กรองอุดตันในช่วงฝุ่นหนามาก จึงไม่มีค่าในช่วงที่ PM2.5 สูงที่สุด เอนเอียงแน่นอน และแก้ด้วยข้อมูลที่มีไม่ได้ทั้งหมด

ตัวอย่างผลของ MNAR: ถ้าค่าหายเฉพาะชั่วโมงที่ PM2.5 > 150 ค่าเฉลี่ยรายวันจากชั่วโมงที่เหลือจะต่ำกว่าความจริง และ จำนวนวันที่เกิน 37.5 µg/m³ จะถูกนับน้อยกว่าความจริง ซึ่งเป็นคำถามหลักของหลายคนใน questions.md

ข้อควรจำ: เราพิสูจน์ MCAR ได้ยาก และพิสูจน์ MNAR จากข้อมูลชุดเดียวไม่ได้ เพราะค่าที่ใช้ตัดสินหายไปแล้ว สิ่งที่ทำได้คือหา หลักฐานแวดล้อม และระบุสมมติฐานของเราให้ชัด

3. หาหลักฐานด้วย missingno และ pandas

3.1 ภาพรวมด้วย missingno

missingno ทำงานกับ DataFrame แบบกว้าง ให้ pivot เป็น แถว = ชั่วโมง, คอลัมน์ = สถานี

import missingno as msno

wide = hourly.pivot(index="ts", columns="station_id", values="pm25")

msno.matrix(wide)          # แถบขาว = ช่วงที่หาย ดูว่าหายเป็นช่วงยาวหรือกระจาย
msno.bar(wide)             # สัดส่วนข้อมูลที่มีของแต่ละสถานี
msno.heatmap(wide)         # สถานีใดมักหายพร้อมกัน (nullity correlation)
ภาพ ถ้าเห็นแบบนี้ ตีความเบื้องต้น
matrix แถบขาวยาวแนวนอนตัดทุกสถานีพร้อมกัน ปัญหาจากระบบส่วนกลางหรือการดึงข้อมูลของเราเอง ไม่ใช่เซนเซอร์
matrix แถบขาวยาวเฉพาะสถานีเดียว สถานีเสียหรือปิดซ่อม
heatmap สถานีในจังหวัดเดียวกันหายพร้อมกัน (ค่าใกล้ 1) ปัญหาไฟฟ้า/เครือข่ายในพื้นที่ (MAR ตามพื้นที่)

ถ้ามีสถานีมาก ภาพจะอ่านยาก ให้เลือกเฉพาะสถานีในภูมิภาคที่ตอบคำถามของตนเอง เช่น wide[["35t", "36t"]] (ใช้รหัสสถานีจริงจากตาราง stations)

3.2 การสูญหายสัมพันธ์กับเวลาหรือไม่

hourly["is_na"] = hourly["pm25"].isna()

hourly.groupby(hourly["ts"].dt.hour)["is_na"].mean()            # ตามชั่วโมงของวัน
hourly.groupby(hourly["ts"].dt.dayofweek)["is_na"].mean()       # ตามวันในสัปดาห์ (0 = จันทร์)
hourly.groupby(hourly["ts"].dt.to_period("M"))["is_na"].mean()  # ตามเดือน

ถ้าหายมากเฉพาะวันใดวันหนึ่งของสัปดาห์ช่วงกลางวัน เป็นหลักฐานของการซ่อมบำรุงตามรอบ (MAR ตามเวลา) ถ้าหายมากในเดือนกุมภาพันธ์–เมษายน ซึ่งเป็นช่วงหมอกควันภาคเหนือ ให้สงสัย MNAR

3.3 การสูญหายสัมพันธ์กับตัวแปรอื่นหรือไม่

เราไม่เห็นค่า PM2.5 ที่หายไป แต่เห็น ตัวแทน (proxy) ได้ เช่น PM10 ของชั่วโมงเดียวกัน หรือ PM2.5 ของชั่วโมงก่อนหน้า

hourly = hourly.sort_values(["station_id", "ts"])
hourly["pm25_prev"] = hourly.groupby("station_id")["pm25"].shift(1)

# PM10 และ PM2.5 ชั่วโมงก่อนหน้า ตอนที่ PM2.5 หาย เทียบกับตอนที่มีค่า
hourly.groupby("is_na")[["pm10", "pm25_prev"]].median()

ถ้าค่ามัธยฐานของ pm10 และ pm25_prev ในกลุ่มที่หาย สูงกว่า กลุ่มที่มีค่าอย่างชัดเจน แปลว่าค่ามักหายตอนฝุ่นหนา เป็นหลักฐานสนับสนุน MNAR (หรืออย่างน้อย MAR ที่ขึ้นกับระดับมลพิษ) ให้ตรวจแยกสถานีด้วย เพราะผลรวมอาจซ่อนความต่างระหว่างสถานี

4. ทางเลือกในการจัดการ และ trade-off

ไม่มีวิธีที่ “ถูกที่สุด” มีแต่วิธีที่เหมาะกับคำถามและสมมติฐานเรื่องกลไกการสูญหาย

วิธี ทำอย่างไร ข้อดี ข้อเสีย / ความเสี่ยง เหมาะเมื่อ
ทิ้งแถวที่ว่าง (drop) dropna() แล้วคำนวณจากที่เหลือ ง่าย ไม่สร้างค่าปลอม ค่ารายวันคำนวณจากกี่ชั่วโมงก็ได้ วันที่มี 3 ชั่วโมงหนักเท่าวันที่มี 24 ชั่วโมง MCAR และหายน้อย
Complete-case ตามเกณฑ์ความครบ ใช้เฉพาะวันที่ n_hours >= 18 จาก 24 (75%) ค่ารายวันเชื่อถือได้ เกณฑ์ 75% เป็นแนวปฏิบัติที่ใช้กันทั่วไปในการรายงานคุณภาพอากาศ ทิ้งวันไปจำนวนหนึ่ง และถ้าเป็น MNAR จะทิ้งวันที่ฝุ่นหนาที่สุดไปด้วย ทุกกรณีที่คำนวณค่าเฉลี่ย 24 ชั่วโมงเทียบมาตรฐาน
Interpolation ช่วงสั้น เติมเส้นตรงตามเวลาเฉพาะช่วงที่หาย ≤ 3 ชั่วโมง PM2.5 เปลี่ยนช้าในช่วงสั้น ค่าเติมจึงใกล้ความจริง ช่วยให้วันผ่านเกณฑ์ความครบมากขึ้น ลดความแปรปรวน ตัดยอดที่เกิดในช่วงที่หาย ช่องว่างสั้นจาก MCAR/MAR
Imputation เติมด้วยค่ามัธยฐานของสถานี, ค่าเฉลี่ยตามชั่วโมงของวัน หรือ KNNImputer จากสถานีใกล้เคียง (เสริม) ได้ข้อมูลครบทุกช่อง สร้างค่าที่ไม่ได้วัดจริง ทำให้ความไม่แน่นอนดูน้อยกว่าความจริง ถ้า MNAR จะเติมค่าต่ำเกินไป ใช้เพื่อวาดภาพหรือโมเดล ไม่ใช่เพื่อนับวันเกินมาตรฐาน
เก็บไว้เป็น NULL + flag ไม่เติม แต่เพิ่มคอลัมน์บอกสถานะ โปร่งใสที่สุด ผู้ใช้ปลายทางต้องจัดการเอง ใช้ร่วมกับทุกวิธีข้างต้น

ข้อควรระวังเรื่อง interpolation ใน pandas

Series.interpolate(limit=3) ไม่ได้ แปลว่า “เติมเฉพาะช่องว่างที่ยาวไม่เกิน 3” แต่แปลว่า “เติมไม่เกิน 3 ช่องแรกของทุกช่องว่าง” ช่องว่าง 10 ชั่วโมงจึงถูกเติม 3 ชั่วโมงแรก ซึ่งไม่ใช่สิ่งที่ต้องการ ต้องวัดความยาวช่องว่างเอง

def fill_short_gaps(s: pd.Series, max_gap: int = 3) -> pd.Series:
    """เติมเส้นตรงตามเวลาเฉพาะช่องว่างที่ยาวไม่เกิน max_gap ชั่วโมง (s ต้องมี DatetimeIndex)"""
    is_na = s.isna()
    run_id = (is_na != is_na.shift()).cumsum()          # เลขกลุ่มของช่วงที่ต่อเนื่องกัน
    run_len = is_na.groupby(run_id).transform("sum")    # ความยาวของช่วงที่ว่าง
    short = is_na & (run_len <= max_gap)
    filled = s.interpolate(method="time", limit_area="inside")
    return s.where(~short, filled)

limit_area="inside" ทำให้ไม่เติมช่องว่างที่หัวหรือท้ายข้อมูล ซึ่งไม่มีค่าทั้งสองฝั่งให้อ้างอิง

5. การตัดสินใจทำให้คำตอบเอนเอียงอย่างไร

ทุกการตัดสินใจเปลี่ยนคำตอบของ questions.md ได้ ตัวอย่างกับคำถาม “เชียงใหม่มีกี่วันในเดือนมีนาคมที่ PM2.5 เฉลี่ย 24 ชั่วโมงเกิน 37.5 µg/m³”

การตัดสินใจ ผลต่อคำตอบ
ทิ้ง NULL แล้วเฉลี่ยทุกวัน วันที่มีข้อมูลแค่ช่วงเช้าที่ฝุ่นน้อยอาจถูกนับว่า “ไม่เกิน”
ใช้เฉพาะ n_hours >= 18 ถ้าค่าหายตอนฝุ่นหนา (MNAR) วันที่แย่ที่สุดถูกตัดทิ้ง จำนวนวันเกินมาตรฐานต่ำกว่าความจริง
เติมช่องว่างด้วยค่ามัธยฐานทั้งเดือน ยอดของวันที่ฝุ่นหนาถูกดึงลง
รายงาน “เกิน X จาก Y วันที่มีข้อมูลครบ” ซื่อตรงที่สุด ผู้อ่านเห็นทั้งตัวตั้งและตัวหาร

วิธีที่ดีคือทำ sensitivity analysis อย่างง่าย: คำนวณคำตอบภายใต้หลายเกณฑ์ (เช่น n_hours >= 12, >= 18, = 24) ถ้าคำตอบเปลี่ยนมาก ต้องรายงานความไม่แน่นอนนั้นด้วย ไม่ใช่เลือกเกณฑ์ที่ได้ผลถูกใจ

สรุป

  • ข้อมูลสูญหายมีทั้งค่า NULL และแถวที่หายไป ต้องสร้าง full grid จึงจะเห็นครบ
  • MCAR ไม่ทำให้เอนเอียง MAR แก้ได้ถ้าคำนึงถึงตัวแปรที่เกี่ยวข้อง MNAR เอนเอียงแน่นอนและพิสูจน์จากข้อมูลไม่ได้
  • missingno ช่วยเห็นรูปแบบ ส่วน pandas ช่วยทดสอบว่าการสูญหายสัมพันธ์กับเวลา สถานี หรือระดับมลพิษ
  • เกณฑ์ n_hours >= 18, interpolation ช่วงสั้น และ imputation ต่างมี trade-off ต้องเลือกตามคำถาม
  • ทุกการตัดสินใจต้องบันทึกใน data_dictionary.md พร้อมผลที่อาจทำให้คำตอบเอนเอียง

คำถามทบทวน

  1. ยกตัวอย่างสถานการณ์ของข้อมูล PM2.5 ที่เป็น MCAR, MAR และ MNAR อย่างละ 1 ตัวอย่างที่ต่างจากในเอกสาร
  2. ทำไม isna().mean() บนตาราง measurements จึงอาจประเมินการสูญหายต่ำเกินจริง
  3. ถ้าพบว่า PM10 ในชั่วโมงที่ PM2.5 หายสูงกว่าปกติ ควรสรุปอะไรและไม่ควรสรุปอะไร
  4. ทำไมไม่ควรใช้ค่าที่เติมด้วย imputation ไปนับจำนวนวันที่เกินมาตรฐาน
  5. interpolate(limit=3) ต่างจาก fill_short_gaps(max_gap=3) อย่างไร
