Pipeline ที่ต้องทำงานครบ

สี่ขั้นจากศูนย์ถึงข้อมูลสะอาด

ขั้น คำสั่ง ตรวจอย่างไร
1. ดึงข้อมูล python src/fetch_air4thai.py ไฟล์ JSON ใหม่ ขนาดไม่เป็นศูนย์
2. โหลด python src/load_duckdb.py SELECT count(*), max(ts) FROM measurements
3. ตรวจคุณภาพ python src/validate.py exit code 0 + WARN ที่อธิบายได้
4. ทำความสะอาด python src/clean.py n_hours อยู่ใน 0–24, ไม่มี key ซ้ำ

src/run_pipeline.py (แนะนำ)

STEPS = ["src/fetch_air4thai.py", "src/load_duckdb.py",
         "src/validate.py", "src/clean.py"]

for step in STEPS:
    print(f"\n==> {step}")
    subprocess.run([sys.executable, step], check=True)   # exit code ไม่ใช่ 0 จะหยุด
print("\nPipeline เสร็จสมบูรณ์")
  • check=True: หยุดทันทีเมื่อขั้นใดล้มเหลว
  • sys.executable: ทุกขั้นใช้ Python ของ dstoolbox ตัวเดียวกัน

ถ้า Air4Thai ล่มในวันนำเสนอ

API ล่มไม่ใช่ความผิดของผู้เรียน แต่ การไม่มีแผนสำรอง เป็นความรับผิดชอบของผู้เรียน

  1. คัดลอก JSON ดิบที่ดึงไว้ หรือ data/sample/ เข้า data/raw/
  2. ข้ามขั้นที่ 1 แล้วรันขั้นที่ 2–4
  3. เขียนวิธีนี้ใน README หัวข้อ “ถ้าดึงข้อมูลไม่ได้”

รูปแบบการนำเสนอ

10 นาที: demo 7 + ถาม-ตอบ 3

นาทีที่ ส่วน สิ่งที่ต้องแสดง
0–1 คำถามและแหล่งข้อมูล คำถาม 1–2 ข้อจาก questions.md

นำเสนอจากเครื่องตนเอง เริ่มจากสถานะไม่มีฐานข้อมูล ระหว่างรอ pipeline ให้อธิบายแต่ละขั้น

Warning

นโยบาย AI: อธิบายส่วนใดของโค้ดที่ส่งไม่ได้ อาจไม่ได้คะแนนเกณฑ์ที่เกี่ยวข้องกับส่วนนั้น

ระดับพอใช้ได้ประมาณครึ่ง เช่น ต้องแก้เล็กน้อยระหว่าง demo, เพื่อนต้องถาม 1–2 จุด, เหตุผลไม่โยงกับคำถาม, commit รวบครั้งเดียว, เกินเวลาเล็กน้อย คะแนนเกณฑ์ 2 มาจากแบบบันทึก fresh clone test ของเพื่อน

Fresh clone test

  • สลับเครื่องกับคู่ (ระบบปฏิบัติการต่างกันถ้าได้)
  • เพื่อนทำตาม README โดยเจ้าของห้ามพูดหรือชี้ — จดอย่างเดียว
  • ไม่เกิน 25 นาทีต่อคน
  • ผลบันทึกเป็นความคิดเห็นใน PR → แก้ทุกจุดที่ “ต้องถามหรือแก้”

Tip

วิธีเดียวที่จับขั้นตอนที่ “เจ้าของทำไปแล้วจนลืม” ได้

ปัญหาที่พบบ่อยบนเครื่องเพื่อน

อาการ วิธีแก้
FileNotFoundError: data/raw/... ให้ script สร้างเอง Path(...).mkdir(parents=True, exist_ok=True)
ModuleNotFoundError ใส่แพ็กเกจใน environment.yml แล้วทดสอบด้วย env ใหม่
path C:\Users\... ในโค้ด ใช้ path สัมพัทธ์จาก root ของ repo
รันได้เฉพาะเมื่อรัน notebook ก่อน ย้ายขั้นสำคัญเข้า src/ + run_pipeline.py
load_duckdb.py รันซ้ำแล้วข้อมูลซ้ำ ทำให้การโหลดเป็น idempotent

ซ้อมกับเพื่อนและจับเวลา

  • demo จบใน 7 นาที — เกินให้ ตัดเนื้อหา ไม่ใช่พูดเร็วขึ้น
  • live demo เริ่มจากไม่มีฐานข้อมูลจริง
  • อธิบายได้ว่าทำไมแบ่ง fail / warn แบบนี้
  • บอกได้ว่าเกณฑ์ n_hours ทำให้คำตอบเอนเอียงไปทางใด
  • ตอบเรื่องโค้ดส่วนที่ใช้ AI ช่วยได้

เตรียมหน้าจอ: เปิดไฟล์เป็น tab ตามลำดับ, ขยายตัวอักษร, รัน notebook ไว้ล่วงหน้า, ปิดการแจ้งเตือน ปิด kernel ที่ถือ connection ก่อน demo
