## ขั้นที่ 2: ซ้อมนำเสนอแบบจับเวลา

ซ้อมกับเพื่อนในกลุ่ม 3 คน ผลัดกันเป็น *ผู้นำเสนอ* *ผู้จับเวลา* และ *ผู้ถาม*

1. ผู้นำเสนอพูดตามลำดับในคู่มือ (10 นาที) ผู้จับเวลาบอกเมื่อถึงนาทีที่ 5, 8 และ 10
2. ผู้ถามเลือกคำถาม 2 ข้อจากตารางตัวอย่างคำถามในคู่มือ และขอให้อธิบายโค้ด 1 ฟังก์ชันที่ชี้แบบสุ่ม
3. จดผลซ้อมตามตารางนี้ แล้วปรับก่อนวันจริง

| ประเด็น | ผลซ้อม | สิ่งที่จะแก้ |
|---|---|---|
| เวลาที่ใช้จริง | ... นาที | |
| ข้อค้นพบหลักชัดใน 1 นาทีแรกหรือไม่ | | |
| demo ติดขัดตรงไหน | | |
| คำถามที่ตอบไม่ได้ / ตอบไม่มั่นใจ | | |
| โค้ดส่วนที่ต้องทบทวน | | |

เตรียมแผนสำรอง: ภาพหน้าจอแดชบอร์ดแต่ละระดับ และ `report.html` ที่เปิดได้แบบ offline

## ขั้นที่ 3: Fresh-clone + run dashboard test ให้เพื่อน

ทำ **ก่อนวันนำเสนออย่างน้อย 2 วัน** เพื่อให้เจ้าของ repo มีเวลาแก้ ผู้ทดสอบทำตาม README ของเพื่อนเท่านั้น ห้ามแก้ไฟล์เอง และห้ามเจ้าของช่วยพูด

```bash
git clone https://github.com/<เพื่อน>/<repo>.git final-test
cd final-test
git checkout main
# ทำตาม README ทุกขั้น: สร้าง env → run_all.py (หรือไฟล์ตัวอย่างจากผู้สอน) → render รายงาน → เปิด app
```

เปิด issue ใน repo ของเพื่อน หัวข้อ `Final fresh-clone test` ด้วยแบบฟอร์มนี้

```markdown
**ผู้ทดสอบ:** ... · **วันที่:** ... · **OS:** Windows / macOS / Linux · **commit ที่ทดสอบ:** (git rev-parse --short HEAD)

| ขั้น | ผล | เวลา | หมายเหตุ / error |
|---|---|---|---|
| สร้าง environment | ผ่าน / ไม่ผ่าน | ... นาที | |
| run_all.py | ผ่าน / ใช้ไฟล์ตัวอย่าง / ไม่ผ่าน | | |
| quarto render | ผ่าน / ไม่ผ่าน | | |
| เปิด app | ผ่าน / ไม่ผ่าน | | |
| drill-down 4 ระดับ + ย้อนกลับ | ผ่าน / ไม่ผ่าน | | |
| ตัวกรองวันที่ทำงานทุกระดับ | ผ่าน / ไม่ผ่าน | | |

**README ส่วนที่ไม่ชัด:** ...
```

เจ้าของ repo แก้ตาม issue, commit โดยอ้างเลข issue (เช่น `แก้ path ของฐานข้อมูลใน app (fixes #12)`) แล้วขอให้ผู้ทดสอบยืนยันก่อนปิด issue

## ขั้นที่ 4: ติด tag `v1.0` และส่งงาน

เมื่อทุกข้อในขั้นที่ 1 ผ่านและ issue ปิดแล้ว

```bash
git switch main && git pull
git tag -a v1.0 -m "โครงการสุดท้าย: ส่งเพื่อนำเสนอ"
git push origin v1.0
```

ส่งในระบบส่งงานของรายวิชา: ลิงก์ repo, ลิงก์ tag `v1.0`, ลิงก์ issue ที่ตนเองเปิดให้เพื่อน และไฟล์ `report.html`

> ถ้าต้องแก้หลังติด tag ก่อนกำหนดส่ง ให้สร้าง tag ใหม่ `v1.1` แทนการลบ tag เดิม และแจ้งผู้สอน

## ขั้นที่ 5: แบบประเมินเพื่อน (วันนำเสนอ)

ระหว่างฟังการนำเสนอ ให้ประเมินเพื่อนตามที่ผู้สอนกำหนด (อย่างน้อย 3 คน) ผ่านแบบฟอร์มที่ผู้สอนแจก โดยใช้หัวข้อต่อไปนี้ คะแนนนี้เป็นส่วนหนึ่งของ peer review 10% ทั้ง *คะแนนที่ได้รับ* และ *คุณภาพของความคิดเห็นที่ให้*

```markdown

| หัวข้อ | 1 | 2 | 3 | 4 |
|---|---|---|---|---|

(1 = ต้องปรับปรุงมาก · 2 = พอใช้ · 3 = ดี · 4 = ดีเยี่ยม)
```
