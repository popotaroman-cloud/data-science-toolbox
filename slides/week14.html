Data storytelling

Notebook ≠ Report

ผู้อ่านไม่ต้องการเห็น ทุกอย่างที่เราทำ แต่ต้องการรู้ สิ่งที่เราพบ และ เชื่อได้แค่ไหน

Notebook (สำรวจ) Report (สื่อสาร)
เรียงตามลำดับที่เราทำ เรียงตามคำถามของผู้อ่าน
มีทุกกราฟ รวมถึงทางตัน เฉพาะกราฟที่ตอบคำถาม
ผู้อ่านคือตัวเราเอง ผู้อ่านคือคนที่ไม่ได้อยู่ในห้อง
โค้ดเด่น ข้อค้นพบเด่น โค้ดซ่อนไว้

โครงสร้างที่แนะนำ

  1. สรุปสำหรับผู้บริหาร 3–5 bullet: ข้อค้นพบหลักของแต่ละคำถาม
  2. ข้อมูลและวิธีการ แหล่งข้อมูล ช่วงเวลา จำนวนสถานี การทำความสะอาด (สั้น ๆ)
  3. คำถามที่ 1, 2, … → ข้อค้นพบ → หลักฐาน → ความมั่นใจ
  4. ข้อจำกัด
  5. ข้อเสนอแนะ / คำถามต่อไป
  6. ภาคผนวก data dictionary, การใช้ AI

หลักสามข้อ

  1. ข้อค้นพบมาก่อน (finding first)
    • ❌ “ผลการวิเคราะห์รายภาค”
    • ✅ “ภาคเหนือมีวันเกินมาตรฐานมากกว่าภาคอื่นราว 3 เท่า โดยกระจุกในเดือน มี.ค.–เม.ย.”
  2. เลือกกราฟอย่างตั้งใจ หนึ่งกราฟหนึ่งประเด็น + เส้นมาตรฐาน 37.5 (และ WHO 15) µg/m³
  3. บอกข้อจำกัดตรงไปตรงมา สถานีกระจุกในเมือง, ข้อมูลขาดหาย, outlier ที่ไม่แน่ใจ, MAUP, ความสัมพันธ์ ≠ เหตุและผล

Quarto: รายงานที่สร้างจากโค้ด

Quarto คืออะไร

  • .qmd = Markdown + code chunk → HTML, PDF หรือ Word
  • รันโค้ดจริงทุกครั้งที่ render → ตัวเลขตรงกับข้อมูลเสมอ
  • ไม่ต้องคัดลอกกราฟไปวาง
quarto render report/report.qmd      # ได้ report/report.html
quarto preview report/report.qmd     # เปิด browser และ render ใหม่เมื่อบันทึก

YAML header

format:
  html:
    toc: true
    code-fold: true
    embed-resources: true
execute:
  echo: false
ตัวเลือก ความหมาย
execute: echo: false ซ่อนโค้ดทั้งรายงาน แสดงเฉพาะผล
code-fold: true ถ้าเปิด echo ให้โค้ดพับไว้ กดดูได้
embed-resources: true รวม CSS/JS/รูป (รวม Plotly) ในไฟล์ HTML เดียว
jupyter: python3 ใช้ kernel Python ของ environment โครงการ

DuckDB แบบ read-only + cache

@st.cache_resource                       # สร้าง connection ครั้งเดียว ใช้ร่วมกันทุก session
def get_con():
    return duckdb.connect(str(DB_PATH), read_only=True)

@st.cache_data(ttl=600)                  # cache ผล query (DataFrame) 10 นาที
def query(sql: str, params: tuple = ()):
    return get_con().cursor().execute(sql, list(params)).df()
  • DB_PATH = Path(__file__).resolve().parents[1] / "data" / "pm25.duckdb"

cache_resource vs cache_data

st.cache_resource st.cache_data
เก็บอะไร object ใช้ร่วมกัน: connection, โมเดล ผลที่ serialize ได้: DataFrame
ได้ค่าแบบใด object ตัวเดิม (shared) สำเนาใหม่ทุกครั้ง
key ของ cache argument ของฟังก์ชัน argument (sql, params)

ทำไมออกแบบแบบนี้

  • read_only=True แดชบอร์ดอ่านอย่างเดียว · หลาย process อ่านพร้อมกันได้
    • แต่ขณะ app เปิดอยู่ script ที่ต้อง เขียน จะเปิดไฟล์ไม่ได้ → ปิด app ก่อนรัน pipeline
  • .cursor() แต่ละ session รันใน thread ต่างกัน → cursor ปลอดภัยกว่าใช้ connection ข้าม thread
  • ? parameter แทนต่อ string → กัน SQL injection + cache key ชัดเจน

Drill-down ด้วย session_state

st.session_state = dictionary ที่อยู่รอดข้าม rerun ของ session เดียวกัน

ss = st.session_state
for k in ("region", "province", "station"):
    ss.setdefault(k, None)

def drill(level, widget_key):           # callback: รันก่อน script รอบใหม่
    ss[level] = ss[widget_key]
    ss[widget_key] = None

สี่ระดับของแดชบอร์ด

ระดับ สถานะ แสดงอะไร (ตัวอย่าง)
1 ประเทศ ทุกค่าเป็น None KPI ทั้งประเทศ, bar รายภาค, แผนที่สถานี
2 ภาค region มีค่า bar รายจังหวัด, line รายเดือน
3 จังหวัด province มีค่า สถานีในจังหวัด, time series เทียบสถานี
4 สถานี station มีค่า time series รายวัน, วันเกินมาตรฐาน, outlier flags, cluster

Reproducibility: คนอื่นรันได้ไหม

สิ่งที่ต้องมี

องค์ประกอบ สิ่งที่ต้องมี
สภาพแวดล้อม environment.yml (หรือ pyproject.toml + uv.lock) ครบตามที่ import จริง
ขั้นตอนรัน script เดียว เช่น run_all.py หรือขั้นตอนใน README ที่คัดลอกไปรันได้
path ไม่มี path absolute · ใช้ Path(__file__).resolve().parents[1]
ข้อมูล ไม่ commit data/ แต่บอกวิธีสร้างใหม่ + ทางเลือกเมื่อ API ล่ม
ความลับ / ความสุ่ม .env + .env.example · ตั้ง random_state / Faker.seed ทุกที่
เอกสาร README: คืออะไร ติดตั้ง รัน ผลอยู่ที่ไหน ข้อจำกัด
