เมทริกซ์ monthly profile

  • หนึ่งแถว = หนึ่งสถานี · หนึ่งคอลัมน์ = ค่าเฉลี่ย PM2.5 ของเดือนนั้น
  • สร้างจาก ข้อมูลรายวันที่ทำความสะอาดแล้ว ใน DuckDB
profile = monthly.pivot(index="station_id", columns="m", values="pm25")
print(profile.shape)                 # เช่น (80, 12)

keep = profile.isna().sum(axis=1) <= 2
profile_filled = profile[keep].apply(lambda col: col.fillna(col.mean()))
print(f"ตัดออก {(~keep).sum()} สถานี")

Tip

scikit-learn รับค่าว่างไม่ได้ · บันทึกจำนวนสถานีที่ถูกตัด ไว้ในข้อจำกัด

ทำไมต้อง scale

  • PCA และ KMeans ใช้ ระยะทาง และ ความแปรปรวน
  • มี.ค. ภาคเหนือแกว่ง 20–120 µg/m³ · ก.ค. แกว่งแค่ 5–20 µg/m³
  • ไม่ scale → ผลเกือบเท่ากับ “ดูแค่เดือนมีนาคม”
  • ยิ่งชัดเมื่อรวมตัวแปรต่างหน่วย: PM2.5 กับ CO หรือละติจูด
from sklearn.preprocessing import StandardScaler

X = StandardScaler().fit_transform(profile_filled)   # แต่ละเดือน: mean 0, sd 1

Scale แบบไหน ให้ตรงกับคำถาม

วิธี ทำอะไร กลุ่มที่ได้สะท้อน
scale ตามคอลัมน์ (StandardScaler) ทุกเดือนน้ำหนักเท่ากัน ทั้ง ระดับ และ รูปร่าง ของฤดูกาล
หารแต่ละแถวด้วยค่าเฉลี่ยสถานีก่อน ตัดผลของระดับรวมออก รูปร่าง ของฤดูกาลอย่างเดียว

ไม่มีวิธีใดถูกเสมอ → เขียนเหตุผลที่เลือกไว้ใน notebook

PCA: ลดมิติเพื่อมองเห็นโครงสร้าง

Principal Component Analysis

  • หาทิศทางใหม่ (PC) ที่ข้อมูลแปรปรวนมากที่สุด
  • PC1 อธิบายได้มากสุด · PC2 รองลงมาและตั้งฉากกับ PC1
from sklearn.decomposition import PCA

pca = PCA(n_components=3, random_state=42)
scores = pca.fit_transform(X)
print(pca.explained_variance_ratio_.round(2))   # เช่น [0.71 0.15 0.05]

การตีความ PCA

  • explained variance ratio: PC1 + PC2 เกิน ~80% → กราฟ 2 มิติแทนข้อมูลเดิมได้ค่อนข้างดี
  • loadings: น้ำหนักของแต่ละเดือนใน PC ดูทั้งเครื่องหมายและขนาด
รูปแบบ loadings (ตัวอย่าง) ความหมายที่เป็นไปได้
PC1 บวกใกล้เคียงกันทุกเดือน “ระดับรวม”: score สูง = สกปรกทั้งปี
PC2 บวก ก.พ.–เม.ย. ลบ ต.ค.–ธ.ค. “ช่วงเวลาของ peak”: เหนือ vs กลาง

ข้อควรระวังและ UMAP

Warning

เครื่องหมายของ PC สลับได้ (คูณ −1 ก็ยังเป็นคำตอบเดียวกัน) อย่าตีความว่า “บวก = ดี” ให้ดู การตรงข้ามกัน ของเดือน · ชื่อ PC เป็นการตีความของเราเอง

UMAP (เสริม)

  • ลดมิติแบบไม่เชิงเส้น เห็นกลุ่มย่อยดีกว่า PCA
  • ระยะห่างระหว่างกลุ่ม ไม่มีความหมายเชิงปริมาณ
  • ผลเปลี่ยนตาม n_neighbors → ใช้ สำรวจ ไม่ใช่ สรุป

KMeans: จัดกลุ่มสถานี

KMeans

  • แบ่งเป็น k กลุ่ม แต่ละจุดอยู่ใกล้ centroid ของกลุ่มมากที่สุด
  • ต้องกำหนด k เอง
from sklearn.cluster import KMeans
from sklearn.metrics import silhouette_score

for k in range(2, 8):
    km = KMeans(n_clusters=k, n_init=10, random_state=42).fit(X)
    print(k, round(km.inertia_, 1), round(silhouette_score(X, km.labels_), 3))

การเลือก k: ใช้สามเกณฑ์ร่วมกัน

เกณฑ์ ดูอย่างไร ข้อจำกัด
Elbow (inertia) จุดที่ inertia ลดลงช้าลงชัดเจน มักไม่มี “ข้อศอก” ชัด
Silhouette score −1 ถึง 1 ยิ่งสูงยิ่งแยกชัด ชอบกลุ่มทรงกลมขนาดใกล้กัน
ความหมายเชิงโดเมน อธิบายแต่ละกลุ่มได้ไหม ตอบคำถามได้ไหม ต้องมีความรู้โดเมน

silhouette ใกล้กัน → เลือกค่าที่อธิบายได้ และไม่มีกลุ่มที่มี 1 สถานี

Cluster เป็นสมมติฐาน ไม่ใช่ความจริง

KMeans จะ คืนกลุ่มให้เสมอ แม้ข้อมูลไม่มีโครงสร้างกลุ่ม

  1. ความเสถียร: เปลี่ยน random_state / ตัดบางสถานี กลุ่มยังคล้ายเดิมไหม
  2. ความหมาย: profile เฉลี่ยแต่ละกลุ่มอธิบายเป็นภาษาคนได้ไหม
  3. ข้อมูลภายนอก: pd.crosstab กับ region
  4. ภาษา: “กลุ่ม A มีแนวโน้ม peak ช่วง มี.ค.” ไม่ใช่ “กลุ่ม A คือ สถานีไฟป่า”

สัปดาห์ที่ 13 จะเอากลุ่มไปวางบนแผนที่ เป็นการตรวจความสมเหตุสมผลอีกชั้น

Outlier: ความผิดพลาด หรือเหตุการณ์จริง

“ต่างมาก” ไม่ได้แปลว่า “ผิด”

ประเภท ตัวอย่างใน PM2.5 ควรทำ
ความผิดพลาด (error) ค่าติดลบ, 999, ค่าซ้ำ 48 ชม., กระโดด 1 ชม. แล้วกลับปกติ แก้ตามกฎ หรือแปลงเป็น missing พร้อมเหตุผล
เหตุการณ์สุดขั้วจริง ไฟป่าภาคเหนือ มี.ค.–เม.ย., หมอกควันข้ามแดน เก็บไว้ มักเป็นสิ่งที่เราสนใจที่สุด
ไม่แน่ใจ สถานีเดียวสูงมาก สถานีใกล้เคียงปกติ ติดธง ตรวจต่อ รายงานทั้งแบบรวม/ไม่รวม

อย่าลบ outlier อัตโนมัติ

  • df = df[df.z.abs() < 3] → ลบ วันที่อากาศแย่ที่สุด ซึ่งสำคัญต่อสุขภาพที่สุด
  • ค่าเฉลี่ยต่ำเกินจริง และซ่อนปัญหา

วิธีตรวจจับ: เทียบกับ “ปกติของบริบทนั้น”

วิธี แนวคิด เหมาะกับ
IQR นอก Q1 − 1.5·IQR ถึง Q3 + 1.5·IQR ภาพรวมเร็ว ๆ (boxplot)
Robust z-score (MAD) 0.6745·(x − median)/MAD เกิน 3.5 ข้อมูลเบ้
STL residual residual ใหญ่ผิดปกติหลังตัด trend/seasonality time series รายสถานี
Isolation Forest (PyOD, เสริม) จุดที่ถูก “แยกออก” ง่ายในหลายมิติ ดูหลายมลพิษพร้อมกัน

เทียบกับค่ากลางทั้งปี → ทุกวันในหน้าเผากลายเป็น outlier หมด

Robust z-score รายสถานี × เดือน

d["month"] = pd.to_datetime(d["date"]).dt.month
g = d.groupby(["station_id", "month"])["pm25_mean"]
med = g.transform("median")
mad = g.transform(lambda s: (s - s.median()).abs().median())
d["robust_z"] = 0.6745 * (d["pm25_mean"] - med) / mad
d["is_outlier"] = d["robust_z"].abs() > 3.5
  • d มาจาก ข้อมูลรายวันที่ทำความสะอาดแล้ว
  • ติดธง เป็นคอลัมน์ใหม่ ไม่ลบแถว

PDPA กับโครงการข้อมูล

ข้อมูลส่วนบุคคลคืออะไร

PDPA พ.ศ. 2562 (บังคับใช้เต็มรูปแบบ 1 มิ.ย. 2565): ข้อมูลที่ระบุตัวบุคคลได้ ไม่ว่าทางตรงหรือทางอ้อม

ประเภท ตัวอย่าง
ระบุตัวตรง ชื่อ–นามสกุล, เลขประจำตัวประชาชน, เบอร์โทร, HN
ระบุตัวทางอ้อม (quasi-identifier) อายุ + เพศ + ตำบล + วันที่เข้ารับบริการ
ข้อมูลอ่อนไหว (มาตรา 26) สุขภาพ, ความพิการ, พันธุกรรม, ศาสนา ฯลฯ ต้องได้รับความยินยอมโดยชัดแจ้ง

PM2.5 + ข้อมูลผู้ป่วย = ข้อมูลอ่อนไหว

  • PM2.5 รายสถานี ไม่ใช่ ข้อมูลส่วนบุคคล
  • ต่อยอดกับการเข้ารับบริการรายคน → ข้อมูลสุขภาพ
  • ตัดชื่อแล้ว แต่ยังมีอายุ เพศ ตำบล วันที่ → ระบุตัวได้ในชุมชนเล็ก

Warning

หลักของรายวิชา: ห้ามนำข้อมูลส่วนบุคคลจริงเข้า repo หรือเครื่องส่วนตัวโดยไม่มีการอนุญาต ต้องผ่านผู้สอนและคณะกรรมการจริยธรรมฯ ก่อน · ระหว่างพัฒนาใช้ ข้อมูลสังเคราะห์ หรือ ข้อมูลรวม (แนวทางวิชาการ ไม่ใช่คำปรึกษาทางกฎหมาย)

Pseudonymization vs anonymization

Pseudonymization Anonymization
ทำอะไร แทนตัวระบุด้วยรหัส เช่น HN → P0001 เก็บกุญแจแยก ทำให้ระบุตัวไม่ได้อีก
ย้อนกลับได้ไหม ได้ ถ้ามีกุญแจ ไม่ควรย้อนกลับได้
ยังเป็นข้อมูลส่วนบุคคลไหม ยังเป็น อยู่ภายใต้ PDPA ถ้าทำได้จริง ไม่อยู่ภายใต้ PDPA
เทคนิค hash + secret key, รหัสสุ่ม aggregate, generalize, ตัดกลุ่มที่มีคนน้อย

ความเสี่ยง re-identification

  • ลบชื่อออกไม่พอ: รหัสไปรษณีย์ + เพศ + วันเกิด ระบุตัวชาวอเมริกันได้ราว 87% (Sweeney)
  • เสี่ยงขึ้นเมื่อข้อมูลละเอียดมาก หรือมีกลุ่มคนน้อย (“อายุ 90+ ในตำบลหนึ่ง” = 1 คน)
  • เสี่ยงขึ้นเมื่อเชื่อมกับข้อมูลภายนอก (social media, ข่าว)
  • k-anonymity: ทุกชุดค่าของ quasi-identifier ต้องมีอย่างน้อย k คน (เช่น k = 5)
  • แนวปฏิบัติ: ไม่แสดงช่องที่นับได้น้อยกว่า 5–10

ข้อมูลสังเคราะห์ (synthetic data)

สามเครื่องมือ สามเป้าหมาย

เครื่องมือ ใช้ทำอะไร รักษาสถิติจริง ความเสี่ยงความเป็นส่วนตัว
Faker (หลัก) ข้อมูลปลอมรูปแบบสมจริง ทดสอบโค้ด/schema/pipeline ไม่ (สุ่มอิสระ) ต่ำมาก
SDV (เสริม) เรียนการแจกแจงจากตารางจริง แล้วสร้างตารางใหม่ ใช่ บางส่วน ไม่ได้ปลอดภัยอัตโนมัติ
SMOTE (เสริม) เพิ่มตัวอย่างกลุ่มน้อยใน classification ไม่ใช่เป้าหมาย —

Faker: ทดสอบ pipeline โดยไม่แตะข้อมูลจริง

  • สร้าง ตารางผู้ป่วยปลอมที่มี schema เดียวกัน กับที่คาดว่าจะได้
  • เขียนโค้ดเชื่อมกับข้อมูลรายวันที่ทำความสะอาดแล้วได้ตั้งแต่วันนี้
from faker import Faker

Faker.seed(42)
fake = Faker("th_TH")
print(fake.name(), "|", fake.date_between(start_date="-1y", end_date="today"))

Warning

จำนวนผู้ป่วยที่สุ่มไม่สัมพันธ์กับ PM2.5 → ห้ามนำผลวิเคราะห์ไปสรุป ใช้ตรวจว่าโค้ดทำงานถูกเท่านั้น

SDV และ SMOTE: ขีดจำกัดที่ต้องรู้

SDV

  • ไม่ได้เป็นส่วนตัวโดยอัตโนมัติ อาจสร้างแถวเกือบเหมือนคนจริงที่หายาก
  • การ fit ต้องใช้ข้อมูลจริง → ยังต้องได้รับอนุญาตก่อน
  • ความสัมพันธ์ซับซ้อน/หายากอาจหาย → ยืนยันกับข้อมูลจริงเสมอ

SMOTE

  • ใช้กับ training set เท่านั้น หลังแบ่ง train/test
  • ไม่ใช่เครื่องมือปกป้องความเป็นส่วนตัว
